## Read Before Editing

1. Read this root AGENTS.md.
2. Identify every file/folder you expect to touch.
3. Walk from repo root to each target, reading every AGENTS.md on the route.
4. Use the nearest AGENTS.md as the local contract; parents for repo-wide rules.
5. If docs conflict, the closer doc wins on local detail — but no child may weaken DOX.

Do not rely on memory. Re-read the applicable DOX chain in the current session before editing.

## Update After Editing

Every meaningful change requires a DOX pass before the task is done. Update the closest owning AGENTS.md when a change affects purpose, scope, durable structure, contracts, workflows, inputs/outputs, constraints, user preferences, or the Child DOX Index. Update parents when parent-level structure/ownership/index changes. Delete stale text immediately.

## Purpose

Public help site for the **tmrw education platform**. Docusaurus static site → GitHub Pages at `https://tmrw-education.github.io/help/`. One knowledge base, multiple product surfaces. See `_internal/HELP_STRATEGY.md` for the layered-help vision (tooltips + KB site + Felix AI).

## Stack

- Docusaurus **3.10.1**, classic preset, `@docusaurus/faster` enabled. React 19. TypeScript.
- Search: `@easyops-cn/docusaurus-search-local` (local index, `/search` page).
- Config: `docusaurus.config.ts`. Sidebars: `sidebars.ts` (single autogenerated config shared by all sections).
- Build: `npm run build` → `build/`. Dev: `npm start`. Typecheck: `npm run typecheck`.
- Deploy: `deploy.yml` lives in the **content** repo (`tmrw-education/help`), not here — it checks out both repos and publishes to GitHub Pages on push to `help`'s `main`, on a daily cron catch-all, and via manual dispatch. Push a tooling-only change here, then trigger a rebuild from `help` (empty commit or manual dispatch) to publish it.
- `docs`/`blog` presets are **off**. Content is served by seven separate `plugin-content-docs` instances (LearnerXP unwired, see Content Map).

## Verification

- `npm run typecheck` — TS check.
- `npm run build` — must pass. Broken links fail it (`onBrokenLinks` and `markdown.hooks.onBrokenMarkdownLinks` are `'throw'`), and that is the publish gate: `deploy.yml` deploys only after a passing build, and also builds (without deploying) on PRs to `help`. A link to a `draft: true` page counts as broken in production. Broken images stay a warning (ZoomImage placeholder).
- `prebuild` runs `scripts/check-content.mjs`, which fails the build when a published (non-draft) page has no content, still says "VERIFY BEFORE PUBLISHING", or (task pages) has no `id` or an id containing its product code. It skips the content root and hidden folders (`help/.claude/`). After renaming ids, run `npm run clear` before building locally: the cached compiled pages keep old URLs.
- Parking content: content `.md` files compile as MDX, so hide text with `{/* Hidden until … */}`, never `<!-- -->` (fails the build). Start the comment with "Hidden until" (the check skips those blocks) and never nest comments (turn inner ones into `[note: …]`). Tables can't hold a comment: move hidden rows below the table inside one. Currently parked: Academic reporting (sxp/11, all drafts) and the Felix agent pages 10-AI/02–09 and 11–15 (drafts) — their links, Troubleshooting entries and glossary rows.
